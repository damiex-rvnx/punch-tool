Semi-Technical Explainer

How Clock-Bot Actually Works

Every piece of the system, what it does, why it exists, and how they talk to each other — explained without assuming you write code.

Part 1 — Every piece of the system
📱
Clock-Bot App
Lives on your phone / browser
The screen you actually interact with. Built with React — a JavaScript framework that draws the UI. When you tap "Set Reminders" it packages up your schedule and sends it to the Cloudflare server. After that your phone's job is done until the notification arrives.
Runs on your device
😺
GitHub & GitHub Pages
Free hosting on GitHub's servers
GitHub stores your code like Google Drive stores documents — with full version history. GitHub Pages takes that code and publishes it as a live website automatically. Every time code is pushed to the branch, GitHub Actions (a built-in robot) rebuilds the app and puts the new version live within minutes.
Free hosting
☁️
Cloudflare Worker
Runs on Cloudflare's global servers
A small piece of server code that runs in the cloud — not on your phone, not on your laptop. It has four jobs: save schedules when you tap Set Reminders, check every minute if any notifications are due, send those notifications out, and answer status questions from the debug panel.
$5/mo
🗄️
Cloudflare KV
Cloudflare's database (attached to the Worker)
KV = Key-Value. The simplest possible database — just a label and what's stored under it. Your schedule gets saved here under your device ID as the label. The cron reads it every minute. Data auto-deletes after 48 hours. No names, no personal info — just times and a device code.
Included in $5/mo
⏱️
Cron Trigger
Built into Cloudflare — runs automatically
A scheduler that wakes up the Cloudflare Worker every 60 seconds, 24/7, whether anyone is using the app or not. It's the heartbeat of the whole system. Without it, nothing would ever fire — notifications would just sit in KV forever waiting.
Included in $5/mo
🔧
Service Worker
Lives inside your browser on your device
A background script the browser keeps running even after you close the Clock-Bot tab. Its only job is to receive incoming push notifications and display them on screen. Think of it as a sleeping security guard who wakes up only when a package (notification) arrives at the door.
Runs on your device
🔔
ntfy.sh
Third-party service — ntfy's servers
iPhone's problem: Apple won't let websites send background notifications. ntfy bridges the gap. The Cloudflare Worker posts a message to ntfy's servers, which relay it through Apple's official notification pipeline (APNs) to the ntfy app on the iPhone. One paid account covers all crew iPhones.
$5/mo
🤖
Web Push (VAPID)
Internet standard — no extra service needed
The protocol Android uses to receive notifications directly. VAPID is just a security standard — it uses a pair of keys (public + private) to prove the notification is really from your server and not a fake. Android and desktop Chrome support this natively. No middle service needed unlike iOS.
Free — built into browsers
Part 2 — What happens when you tap "Set Reminders"
The complete journey — from button tap to locked-screen notification
Follow it top to bottom. Each step hands off to the next.
1

You tap "Set Reminders" on your phone

The app reads your start time, lunch mark, dinner mark, and warning times. It calculates the exact clock time for each notification — e.g. start 7:30 AM + 4h 30m = clock out at 12:00 PM.

Clock-Bot App
Your Phone
2

Browser creates a push subscription

Your browser contacts Google (Android) or Apple (iOS) servers and gets back a unique "address" — like a mailing address for your specific browser on this specific device. This is stored as the push subscription token.

Service Worker
Google / Apple servers
3

App sends the schedule to Cloudflare

The app packages up your device ID, the push subscription "address," your ntfy topic (iPhone only), and the list of notification times — then sends it all to the Cloudflare Worker over a secure HTTPS connection. This is the only moment your phone and the server talk.

Clock-Bot App
Cloudflare Worker
4

Cloudflare saves it to KV and waits

The Worker stores everything in KV under your device ID as the key. Your phone is now completely out of the picture. It can be locked, out of signal, even turned off — nothing changes on Cloudflare's end.

Cloudflare Worker
Cloudflare KV
5

Cron wakes the Worker every 60 seconds

Cloudflare's built-in scheduler fires every minute. The Worker reads all schedules from KV and compares each notification time to the current time. If something is due within a 90-second window — it fires. If not — it goes back to sleep and logs "future: X."

Cron Trigger
Cloudflare Worker
Cloudflare KV
6

Worker routes the notification by device type

If the schedule has an ntfy topic stored → it's an iPhone → send via ntfy.sh. If no ntfy topic → it's Android → send via Web Push directly. Never both. This is why you stopped getting duplicate notifications.

Cloudflare Worker
ntfy.sh (iPhone)
Web Push (Android)
7

Notification appears on your locked screen

For iPhone: ntfy.sh relays the message through Apple's servers (APNs) → ntfy app on the phone wakes up → shows the notification. For Android: Google's servers (FCM) push it to the browser's service worker → service worker displays it. Either way, your phone buzzes with the reminder.

Apple APNs
Google FCM

Part 3 — The secret keys and what they protect
🔑
Secret keys are like passwords — but instead of a human typing them, machines use them automatically to prove identity and encrypt data. None of them are visible in the app's code. They live in Cloudflare's secure environment and are injected at runtime.
🔐
VAPID_PRIVATE_KEY
Stored in Cloudflare → used by the Worker
VAPID stands for Voluntary Application Server Identification. This private key lets the Cloudflare server sign outgoing push notifications with a cryptographic signature. Android's push service (Google FCM) checks that signature and will only deliver the notification if it matches your registered public key. Without it, anyone could spoof notifications from your server.
Analogy: A wax seal on a letter. Only you have the stamp. The recipient can verify the seal is genuine without ever seeing your stamp.
🌐
VAPID_PUBLIC_KEY
Baked into the app's code — visible, intentionally
The public half of the VAPID key pair. This one is NOT secret — it's embedded in the Clock-Bot app and sent to Google/Apple when creating a push subscription. They use it to verify the private key's signature. A key pair works because knowing the public key tells you nothing about the private key.
Analogy: Your mailing address. Everyone can see it and needs it to send you mail. Knowing it doesn't let anyone read your mail.
🔔
NTFY_TOKEN
Stored in Cloudflare → used by the Worker
Your ntfy.sh paid account's API token. When the Worker sends a notification to ntfy.sh, it includes this token in the request header. ntfy uses it to count the message against your paid account's quota (10,000/day) instead of the shared anonymous IP limit (250/day). Before this was set, all requests looked anonymous and hit the limit fast.
Analogy: A membership card. The bouncer (ntfy.sh) sees your card and knows you're a paying member with a higher limit — not a random stranger off the street.
🚀
CLOUDFLARE_API_TOKEN
Stored in GitHub → used by GitHub Actions only
When you push code to GitHub, GitHub Actions automatically redeploys the Cloudflare Worker. To do that, GitHub needs permission to talk to your Cloudflare account. This token is that permission slip — scoped only to deploying Workers, nothing else. It lives in GitHub's secret storage and is never visible in code or logs.
Analogy: A contractor's key card. It opens the server room door but not the executive suite. Limited access on purpose.
📝
GITHUB_TOKEN
Auto-generated by GitHub Actions — you never touch it
GitHub creates this automatically for each Actions run. The deploy script uses it to push the built app files to the gh-pages branch (which is what gets served as the live website). It expires after each run. You never set this — GitHub handles it entirely behind the scenes.
Analogy: A temporary visitor badge that's issued at the door, used once, and shredded when you leave.

Part 5 — What cron actually does every minute
Each bar = one cron run. It wakes up, checks, and goes back to sleep in about 50ms.
Checked — nothing due (future: X)
Checking now
Notification sent!
What it does each run
1. Wake up
2. Read all schedules from KV
3. Compare times to now
4. Send anything due
5. Update KV
6. Log the result
7. Go back to sleep
The timing window
A notification is "due" if it falls within a ±90 second window of now. This compensates for the cron not firing at the exact millisecond — it might fire 10 seconds late, but the 90s window catches it.

Part 6 — How code gets from your laptop to the live website
This happens automatically every time code is pushed. You never manually upload files.
✏️
Code is written and pushed to GitHub
git push → code lands on the claude/crew-clock-app-SDfGg branch in the GitHub repository
🤖
GitHub Actions wakes up automatically
A robot defined in .github/workflows/deploy-pages.yml detects the push and starts running. No human involvement needed.
🔨
It builds the app
Runs npm run build — this takes the React source code (readable by developers) and compiles it into optimised HTML/CSS/JS files a browser can load fast. The output goes into a dist/ folder.
📤
Pushes built files to the gh-pages branch
The built files are pushed to a separate branch called gh-pages. This branch only ever contains the compiled output — never the raw source code. GitHub Pages serves whatever is in this branch.
🌐
Live at lbrito1126.github.io/qwik-crew-clock
GitHub's servers read the gh-pages branch and serve those files to anyone who visits the URL. Usually live within 2–3 minutes of the original push. The Cloudflare Worker gets deployed the same way via a separate workflow file.
Part 7 — Why iPhone and Android work differently

🍎 iPhone path

1
Cloudflare Worker fires → sees ntfyTopic in KV → knows it's an iPhone
2
Worker posts message to ntfy.sh using your NTFY_TOKEN for authentication
3
ntfy.sh forwards it to Apple's APNs servers
4
APNs delivers it to the ntfy app on the iPhone — even when screen is off
⚠️
Apple blocks websites from doing this directly. ntfy exists purely to work around that restriction using a native app Apple does allow.

🤖 Android path

1
Cloudflare Worker fires → no ntfyTopic in KV → knows it's Android
2
Worker encrypts the notification payload using the VAPID keys and sends it to Google's FCM servers
3
Google FCM delivers it to the browser's service worker on the device
4
Service worker decrypts it and displays the notification on the lock screen
✅
Android allows websites to do this natively. No extra app needed. Web Push is a proper open standard that Android browsers support.
